# 벤치마크 결과 — 2026-07 (0.11.0 시점)

스킬 적용(with)과 미적용(without)을 분리 실행하고, 채점을 사람 손과 LLM 자가 평가에서 떼어낸 실험. 0.4.0 실험(README 참고)의 자기참조 한계 — 생성자와 채점자가 같은 세션 — 를 구조로 해소했다.

## 방법

| 축 | 설계 |
|---|---|
| 케이스 | 10종 신규 작성 — 교정 8(보고서·칼럼·이메일·SNS 카피·기획서 표·에세이·수치 함정·사물 주어) + 생성 2(공지 이메일·보고서 단락). 오탐 억제 시험(SNS CTA가 살아남아야 통과) 포함 |
| 오염 방지 | 입력문과 SKILL.md 예문의 15자 연속 일치를 스캔해 0건 확인. 초기 2건 발견 후 재작성 |
| 정답 유출 차단 | 실행자에게는 어설션(채점 정규식)을 제거한 입력 전용본만 제공 |
| 실행 | with: SKILL.md를 지침으로 로드한 에이전트. without: 스킬 접근이 금지된 에이전트에 "자연스럽게 다듬어줘" 수준의 요청만. 상호 독립 |
| 채점 1 — 기계 | `check.py` 어설션 69개(실행 시점): must_absent/must_present 정규식, 길이 하한, 숫자 전수 추출 대 허용 목록 대조(발명 검출) |
| 채점 2 — 블라인드 | 조건을 모르는 별도 판정자에게 케이스별 A/B 쌍(순서 무작위, 5:5 배정) 제시. 기준: 정보 충실 > 목적 적합 > 산문 품질 |

## 결과

| 층 | with | without |
|---|---|---|
| 기계 어설션 | **69/69 (100%)** | 65/69 (94.2%) |
| 블라인드 판정 | 5승 | 5승 |

### without의 실패 4건 — 스킬의 잔여 가치가 있는 곳

| 케이스 | 실패 | 대응 스킬 규칙 |
|---|---|---|
| column-antithesis | "물론 ~하지만" 양비론 골격 잔존 | 양비론·균형 반사 |
| column-antithesis | 출처 없는 "전문가들은" 잔존 | 막연한 권위 호소 |
| essay-overcorrection | 줄표 잔존 | (어설션 설계 오류 — 아래 보정 참고) |
| gen-report-para | 재료에 없는 수치 "4%" 발명 (12%→8%의 산술 파생) | 철칙 2 날조 금지 |

블라인드 판정에서도 gen-report-para는 without이 후속 계획 문장까지 지어낸 것이 결정적 감점 — 기계와 블라인드가 독립적으로 같은 결론에 도달했다.

### with의 블라인드 패배 5건 중 유형화되는 것

- **과교정 2건** — 에세이의 줄표 1개를 삭제(판정: "문장의 호흡을 지움"), 보고서의 범위 문장을 삭제. 스킬이 경고하는 실패 모드가 스킬 적용 조건에서 발생했다.
- **형식 구성 2건** — 이메일 단락·맺음, SNS 게시물 줄바꿈에서 without이 매체 형식을 더 잘 갖춤. 스킬은 문체를 다루고 문서 형식은 다루지 않으므로 예상 범위.

## 발견 — 스킬 내부 모순 1건

줄표 규칙이 두 기준을 함께 말한다: "문단당 1개 이하"(임계)와 "지워도 뜻이 통하면 지운다"(삭제 우선). 에세이의 줄표 1개는 임계 안인데 with 조건이 삭제했고 블라인드 판정은 그 삭제를 감점했다. **임계 안이면 남긴다**로 우선순위를 명확히 하는 것이 다음 릴리스 후보다.

같은 이유로 essay 케이스의 줄표 must_absent 어설션은 설계 오류였다. 1차 실행(69개) 후 제거해 현재 cases.json은 68개다. 이 문서의 수치는 실행 시점 기준이다.

## 한계

- 판정자가 단일 LLM 1회 실행이다. 케이스 수(10)도 통계적 결론에는 부족하다.
- 케이스 설계·실행·판정이 모두 같은 계열 모델이다. 채점 분리로 완화했으나 계열 편향 가능성은 남는다.
- without 94.2%는 이 시점 모델의 기본기가 그만큼 올라왔다는 뜻이다. 스킬의 가치는 전반 향상이 아니라 남은 실패 지점 — 양비론 골격, 무출처 권위, 생성 시 사실·수치 발명 — 의 차단에 있다.

## 재현

```
python3 evals/benchmark/check.py <outputs_dir>
```
`<outputs_dir>`에 케이스별 `{id}.with.txt`, `{id}.without.txt`를 두면 어설션 표를 출력한다. 실행자에게 cases.json을 직접 주지 말 것 — 어설션이 정답 유출이 된다. `id`·`mode`·`input`만 추려 전달한다.
